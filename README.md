# نظام إدارة السائقين والمركبات

واجهة React لإدارة السائقين والمركبات وإصدار البطاقات، متصلة بخادم Laravel API.
تُحفظ سجلات التطبيق والإعدادات والصور في قاعدة بيانات/تخزين الخادم. يُستخدم
LocalStorage لرمز جلسة Sanctum فقط.

## تشغيل API

```bash
cd laravel-api
composer install
# أنشئ .env من .env.example واضبط اتصال قاعدة البيانات
php artisan key:generate
php artisan migrate --seed
php artisan storage:link
php artisan serve --host=127.0.0.1 --port=8000
```

تأكد من تجهيز حساب مدير صالح لتسجيل الدخول؛ الحسابات تُدار في قاعدة بيانات Laravel.

## تشغيل الواجهة

```bash
npm install
npm run dev
```

افتح الرابط الذي يظهر في الطرفية (عادة `http://localhost:5173`). عنوان API الافتراضي
هو `http://127.0.0.1:8000/api`. لتغييره، عرّف `VITE_API_URL` قبل تشغيل Vite.

## API والصلاحيات

- تسجيل الدخول يتم عبر `POST /api/login`، وتُرسل الواجهة رمز Sanctum مع الطلبات المحمية.
- الموظفون والسائقون والمركبات والبطاقات تُقرأ وتُحفظ عبر مسارات Laravel المقابلة.
- المدير يستطيع إدارة جميع السجلات؛ الموظف يستطيع إدارة السجلات التي أنشأها فقط.
- تُدار صلاحيات API عبر Spatie Laravel Permission. بعد نشر التغييرات، شغّل
  `cd laravel-api && php artisan migrate` لإضافة جداول RBAC وربط الأدوار بالمستخدمين
  الحاليين دون إعادة ضبط قاعدة البيانات. الأدوار الأساسية هي `admin` و`employee`
  و`supervisor` و`viewer`. يحصل `admin` على جميع الصلاحيات؛ ويحصل `employee` افتراضيًا
  على عرض السائقين وإنشاء البطاقات؛ ويحصل `viewer` على صلاحيات العرض فقط؛ ويبدأ
  `supervisor` بلا صلاحيات. يستطيع المدير منح صلاحيات إضافية من نموذج المستخدم الحالي.
  تُرسل الصلاحيات الفعالة للمستخدم من `GET /api/user` وتتحقق منها Laravel على كل
  عملية API؛ إخفاء عناصر الواجهة لتحسين التجربة فقط وليس بديلاً عن الحماية.
- لا يلزم إدخال بريد إلكتروني لإنشاء حساب مستخدم. عمود البريد في قاعدة البيانات اختياري
  للمحافظة على عناوين الحسابات القديمة دون فرضه على الحسابات الجديدة.
- إعدادات النظام تُقرأ من `GET /api/settings` ويحدّثها المدير عبر `PUT /api/settings`.
- صور السائقين والمركبات والشعار والتوقيع تُرفع إلى تخزين Laravel العام؛ يلزم تشغيل
  `php artisan storage:link`.

## مسار تجربة

1. سجّل الدخول بحساب مدير موجود في قاعدة البيانات، ثم أضف موظفًا من صفحة "الموظفون"
2. سجّل الخروج ثم الدخول بحساب الموظف الذي أنشأته
3. من الشريط الجانبي اختر "إضافة سائق"
4. أدخل بيانات السائق، ارفع صورته، اختر نوع المركبة، وأدخل بياناتها
5. لاحظ تحديث معاينة البطاقة مباشرة أثناء الكتابة
6. اضغط "إنشاء البطاقة" لحفظ السائق والمركبة والبطاقة على الخادم
7. من صفحة تفاصيل البطاقة اضغط "طباعة البطاقة" لمعاينة الطباعة (بحجم بطاقة هوية حقيقي 85.6×54 مم)
8. سجّل الدخول كمدير لمشاهدة السجلات وإدارة البطاقات والتقارير والإعدادات

## ملاحظات تقنية

- **نقل البيانات القديمة:** السجلات التي أُنشئت سابقًا في LocalStorage لا تُستورد تلقائيًا
  إلى قاعدة البيانات. احتفظ بنسخة منها أو انقلها قبل إزالة بيانات المتصفح القديمة.
- **الإعدادات:** عدد أيام "قريب الانتهاء" ومدة الصلاحية ولون البطاقة والشعار تؤثر مباشرة
  على حالات البطاقات والمعاينة، وتظهر معاينة حيّة للبطاقة في صفحة الإعدادات.
- **الأداء:** الصفحات تُحمَّل عند الحاجة (Code Splitting)، ومكتبة الرسوم البيانية لا تُحمَّل
  إلا في صفحة التقارير.

## هيكلة المشروع

```
src/
  components/   مكونات مشتركة (Button, Input, Modal...) وأخرى خاصة بالبطاقات والسائقين والمركبات
  pages/        صفحات admin و employee
  services/     طبقة الوصول إلى API
  context/      Providers: AuthContext و ToastContext و SettingsContext
  hooks/        useAuth و useToast و useSettings و useAsyncData و usePageTitle
  utils/        دوال مساعدة (تنسيق التاريخ، حالة البطاقة، التحقق)
  routes/       AppRoutes وحراس المسارات (ProtectedRoute, AdminRoute, EmployeeRoute)
```
